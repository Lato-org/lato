Lato Spaces

Source: https://raw.githubusercontent.com/Lato-org/lato_spaces/refs/heads/main/test/dummy/app/views/application/documentation.html.erb

How to use Lato Spaces

lato_spaces adds workspaces or groups to a Lato application. Use it when users must work inside one selected group and application data must be separated by group.

Installation

Requires Rails 8.1.3.1 or newer in the 8.1 series and Lato 3.25.0 or newer. Existing applications must run rails lato:install:migrations and rails db:migrate before deployment. Previous sessions are invalidated.

Add Lato Spaces to the application Gemfile:

gem "lato"
gem "lato_spaces"

Install the engine and run migrations:

bundle
rails lato_spaces:install:application
rails lato_spaces:install:migrations
rails db:migrate

Mount the engine in config/routes.rb:

Rails.application.routes.draw do
  mount LatoSpaces::Engine => "/lato-spaces"

  # ...
end

Import styles in app/assets/stylesheets/application.scss:

@import "lato_spaces/application";

Import JavaScript in app/javascript/application.js:

import "lato_spaces/application"

Add a menu entry to the group selection page, for example in app/views/layouts/lato/_navbar-nav_content.html.erb:

<%= lato_navbar_nav_item :lato_spaces, lato_spaces.root_path do %>
  Spaces
<% end %>

Upgrading from an older version? Read UPGRADING.md for the steps required by each release.

Configuration

Configure group behavior in an initializer:

LatoSpaces.configure do |config|
  config.setgroup_redirect_path = :dashboard_path
  config.setgroup_auto_after_login = false
  config.setgroup_auto_after_login_if_single = true
  config.permit_group_creation = false
  config.permit_group_management = false
  config.permit_group_preferred = false
end
Option Default Use for
setgroup_redirect_path nil Name of a host application route helper without arguments (e.g. :dashboard_path). Users are redirected there after selecting a group. With nil they return to the Spaces page.
setgroup_auto_after_login false Select a group automatically when the user opens the Spaces page without a selected group: the preferred group first, otherwise the first by name. Requires setgroup_redirect_path.
setgroup_auto_after_login_if_single false Same as above, only when the user belongs to exactly one group. Requires setgroup_redirect_path.
group_icon "bi bi-people-fill" Bootstrap Icons class shown on group cards.
group_params %i[name] Permitted group form params.
membership_params %i[email] Permitted membership form params.
permit_group_creation false Allow non-admin users to create groups. The creator becomes the first member.
permit_group_management false Allow non-admin members to manage their own groups (see permissions below).
permit_group_preferred false Allow users to mark a preferred group. It is listed first and used by automatic selection.

Automatic selection runs only when the user visits the Spaces page (lato_spaces.root_path), so make the post-login flow land there. Never permit lato_user_id, lato_invitation_id or lato_spaces_group_id in group_params or membership_params.

Permissions

Users must be logged into Lato. Users with lato_spaces_admin can select and manage all groups. Other users can only select groups where they are current members. Protected requests recheck membership and clear the selected group if access was revoked. 

user = Lato::User.find_by(email: "admin@example.com")
user.update!(lato_spaces_admin: true)
Action Admin Member with permit_group_management Member
Select a group Any group, also from the group page Own groups Own groups
List all groups Yes No No
Create groups Yes With permit_group_creation With permit_group_creation
Rename or delete a group Any group Own groups No
Add registered users Any group Own groups No
Invite unregistered emails Any group Own groups, only if Lato signup is enabled No
Remove members, resend invitations Any group Own groups, except the last registered member No

Groups have no roles yet: with permit_group_management every member has the same powers, including deleting the group and its data. Enable it only for trusted members. Adding members and resending invitations are rate limited.

Invitations

  • The email is normalized (stripped and downcased).
  • A registered user is added immediately. Non-admins see members by email; full names are shown to admins only.
  • An existing pending Lato invitation is reused; otherwise a new invitation is created and emailed.
  • When the invitation is accepted, the membership moves to the new user.
  • A user or invitation can belong to a group only once.
  • Lato invitations bypass auth_disable_signup: when signup is disabled only admins can invite unregistered emails.

What users can do

  • See available groups.
  • Select the active group for the current session.
  • Work only with data that belongs to the selected group.
  • Add or invite users to a group when management is allowed.
  • Choose a preferred group when enabled.

Protecting application pages

Include the group helper in controllers that require a selected group, then require both Lato authentication and group selection. 

class ApplicationController < Lato::ApplicationController
  include LatoSpaces::Groupable
end

class ProjectsController < ApplicationController
  before_action :authenticate_session
  before_action :authenticate_group

  def index
    @projects = Project.for_lato_spaces_group(@session.get(:spaces_group_id))
  end
end

LatoSpaces::Groupable adds these protected methods:

  • authenticate_group: checks that the selected group is still accessible. Otherwise it clears the selection and redirects to the Spaces page (HTML) or responds 403 Forbidden (JSON).
  • session_group_create(group_id): selects a group the user can access, returns false otherwise.
  • session_group_destroy: clears the selected group.

Read @session.get(:spaces_group_id) only in controllers protected by authenticate_group.

Associating application data with groups

Add Lato Spaces associations to application records that must belong to one or more groups. 

class Project < ApplicationRecord
  include LatoSpaces::Associable
end
  • for_lato_spaces_group(group_id): records of a group (nil returns nothing; with an array of ids add .distinct to avoid duplicates).
  • with_lato_spaces_groups / without_lato_spaces_groups: records with or without groups.
  • lato_spaces_group, lato_spaces_group_id: first group of the record.
  • add_to_lato_spaces_group(id), remove_from_lato_spaces_group(id), switch_lato_spaces_group(id): return true or false and add errors to the record on failure.

When records must always belong to exactly one group, add the stricter concerns after LatoSpaces::Associable:

class Project < ApplicationRecord
  include LatoSpaces::Associable
  include LatoSpaces::AssociableRequired
  include LatoSpaces::AssociableUnique
end
  • AssociableRequired: an existing lato_spaces_group_id is required on create. Destroying the association destroys the record: removing it from its group or deleting the group deletes it.
  • AssociableUnique: a record can belong to one group only.
  • Both only affect the models that include them.

Create records with the current selected group, never with a group id from request params:

Project.create!(
  name: "Project 1",
  lato_spaces_group_id: @session.get(:spaces_group_id)
)

Deleting a group removes its memberships and associations, and destroys every AssociableRequired record of the group.

Customizing group forms

rails lato_spaces:install:application copies overridable partials into app/views/layouts/lato_spaces/ (_group-form-extra_content, _membership-form-extra_content, _group-informations_content) and the LatoSpacesMembershipApplication model concern. Edit them to add custom fields or extra information to group and membership pages. Custom fields must also be permitted with group_params or membership_params.
